- **Android**：`com.stratumauth.app`（MuMu 1080×1920）
- **HarmonyOS**：`com.inkchills.auth`（nova 14 Ultra 模拟器）
- **数据**：同一份加密备份还原后对比；验证码内容不写入本报告

## 鸿蒙明显不如安卓

按对日常使用的影响排序。

| 优先级 | 问题 | 鸿蒙现状 | 安卓对照 |
| --- | --- | --- | --- |
| 布局 | 分类管理顶栏抢位 | 「分类管理」与「返回」叠在一起；Row 未拉满宽度，也没有系统返回箭头 | 标题独立，返回是标准导航；溢出菜单管编辑/删除 |
| 布局 | 导入 / 输入密钥顶栏 | 关闭或返回箭头压住标题；导入页顶栏没有状态栏安全区 | Material 顶栏或 bottom sheet，标题与关闭键分开 |
| 布局 | 输入密钥关不掉 | 关闭按钮可点区域只有约 3px 高，完全落在状态栏里（dump `56,137–140,140`）；返回键会把整个应用退到桌面 | Bottom sheet 用「取消 / 添加」，不跟状态栏抢点击 |
| 布局 | 关于页导航 | 右侧粗「返回」按钮，和标题抢空间 | 系统 ActionBar 返回，内容区完整 |
| 表单 | 编辑详情标签粘连 | 「发行方 (如: Google)6/32」标签和字数统计糊成一行 | Outlined 字段，计数在输入框尾部，互不侵占 |
| 表单 | 高级选项被裁切 | 「显示高级选项」后，位数与时间间隔并排，位数输入框右侧被切掉 | 高级区是完整 Outlined 字段，位数 / 间隔并排也不裁切 |
| 还原 | 自定义顺序丢失 | Ranking 会写入，但默认排序仍是字母序，还原后 Aliyun 排在最前 | 同一备份呈现卡西欧、雨云在前的自定义排名 |
| 设置 | 外观选项被砍 | 主题只有跟随系统 / 浅色 / 深色；无动态颜色、主题色、透明状态栏、系统字体 | 五套主题（含系统默认黑、纯黑）+ 动态颜色 + 强调色 + 透明状态栏 + 系统字体 |
| 安全 | 数据库密码备份消失 | `dbPasswordBackup` 加载时强制写成 false，设置页也没有开关 | 「以数据库密码备份」是独立开关 |
| 语言 | 只做了中英 | 系统 / 中文 / English 三项 | 系统默认 + 27 种语言（含繁中、日、韩、阿等） |
| 导入 | 副标题不说文件名 | 一律「选择文件导入」或「查看指南」 | 直接写 `otp_accounts.json`、`aegis-export.json` 等文件名 |
| 导入 | 选得到文件，读不到 | 系统选择器能列出 `Download` 里的 json；点选后 toast「导入失败: No such file or directory」（`ImportSource.readFileBytesFromUri` 的 `fs.openSync(uri)`） | SAF 选出文件后转换器能跑完 |
| 导入 | 若干格式直接放弃 | FreeOTP xml、WinAuth 加密 zip、TOTP Authenticator encrypt、Authenticator Plus SQLCipher 标成未支持 | 对应格式可走文件导入 |
| 图标 | 改图标入口更弱 | 默认是图标网格，搜索和自定义图片不如安卓显眼 | 可搜索列表 +「使用自定义图标」独立项 |
| 平台 | 没有手表端 | 无对应实现 | Wear OS 同步服务存在 |

### Settings.ets 被关掉的能力

加载偏好时若读到 `dbPasswordBackup === true`，立刻写回 `false` 并 flush。页面里也没有对应开关，等于这个功能在鸿蒙上不存在。

生物识别开关有，但依赖先设应用锁密码；这次没有设密码，超时锁定在截图里是灰的，两边行为一致。

### 还原后排序为什么对不上

鸿蒙 `sortOption` 默认 `alphabetical_asc`。备份里的 Ranking 会导入，但不会把排序模式切到「自定义」，所以列表变成字母序。

「锁定排序」只在选了自定义之后才出现；安卓排序菜单里锁图标一直在。这不是功能缺失，但是还原体验更差。

## 第三方导入实测（2026-09-17 下午）

APK 下在 `E:\Downloads`，用 adb 装进 MuMu（`127.0.0.1:16384`）。截图在 `D:\build\compare\screenshots\`，编号 500+ / 550+。

| 步骤 | 结果 |
| --- | --- |
| 安装 | Aegis 3.4.3、andOTP 0.9.0.1、FreeOTP+ 3.4、2FAS 5.6.0 都装上了 |
| Aegis 导入测试 JSON | 「导入条目」页出现 `ImpAegis` / `rfc6238`，能勾选 |
| Aegis 明文导出 | 导出对话框能开；加密开关关掉后会警告「未加密」；SAF 能进 MuMu `Download`。本轮没稳定写出非空新文件，Harmony 侧改用同一份 Aegis 格式 JSON（343 B，含 `ImpAegis`） |
| 鸿蒙选择器 | 「最近」是空的。要走「浏览」→「我的手机」→ `Download`，文件列表正常（555） |
| 鸿蒙点选 json | 立刻 toast「导入失败: No such file or directory」，列表里没有 `ImpAegis`（dump 557） |
| 误触 | 点到「下载」会打开系统「下载与接收」（蓝牙 / 华为分享 / 下载管理器 / WLAN），不是文件目录 |

`readFileBytesFromUri` 第一行就是 `fs.openSync(uri, READ_ONLY)`。选择器给的 URI 打不开，后面的 Aegis/2FAS 解析都不会执行。这和备份还原能读 `.stratum` 不是同一条路径。

2FAS / andOTP / FreeOTP+ 已安装，还没把各自导出再送进鸿蒙；在 URI 读取修掉之前，换来源也会停在同一个 toast。
